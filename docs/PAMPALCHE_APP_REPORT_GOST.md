## 1 Назначение приложения

Приложение «Пока все вместе» представляет собой интерактивное образовательное веб-приложение, выполненное в формате сюжетного семейного путешествия. Его основная задача заключается в организации совместного досуга ребенка и взрослого через чтение, обсуждение, творческую деятельность, решение заданий и знакомство с культурным материалом.

В процессе работы пользователь проходит последовательный маршрут вместе с героиней Пампалче. Приложение построено таким образом, чтобы действия выполнялись поэтапно. Сначала пользователь входит в приложение, затем переходит к карте маршрута, после чего последовательно проходит четыре модуля. Результатом работы становится получение наград, накопление искр и открытие итогового семейного сертификата.

## 2 Используемая программная среда

Для реализации приложения используется клиентская веб-технология. Программа работает в среде операционной системы Windows и запускается как локальное Angular-приложение через встроенный сервер разработки.

В ходе выполнения работы используется следующее программное обеспечение:

- операционная система Windows;
- Node.js и менеджер пакетов `npm`;
- Angular CLI;
- браузер для открытия локального адреса приложения;
- редактор исходного кода для внесения изменений в проект.

Приложение разработано с использованием следующих технологий:

- Angular 21;
- TypeScript;
- SCSS;
- Angular Router.

Назначение выбранной среды заключается в создании одностраничного веб-приложения, в котором пользователь может перемещаться между экранами без полной перезагрузки страницы. Результатом использования данной среды является работающий локальный интерфейс с маршрутами, модулями, визуальными элементами и сохранением прогресса.

## 3 Конфигурация проекта

Исходные файлы приложения расположены в рабочем каталоге проекта. Основная логика экранов и маршрутов размещается в папке `src/app`, а медиафайлы и вспомогательные изображения находятся в каталоге `assets`.

Контент приложения хранится отдельно от программной логики в файле `pampalche_game_content.json`. Такое разделение необходимо для того, чтобы текст модулей, награды, описания шагов и ссылки на медиа можно было изменять без переписывания программного кода. Результатом данного подхода является более удобная поддержка проекта.

Для хранения пользовательского прогресса используется локальное хранилище браузера `localStorage`. В него записываются пройденные модули, ответы, накопленные искры, полученные бейджи и сохраненные семейные результаты.

## 4 Порядок запуска приложения

Перед запуском необходимо открыть каталог проекта в командной строке Windows и убедиться, что все зависимости установлены.

Для запуска приложения используется команда:

`npm start`

Назначение данной команды заключается в запуске локального сервера разработки Angular. В результате выполнения команды в терминале должна появиться информация о сборке проекта и адрес локального запуска, как правило `http://localhost:4200` или `http://127.0.0.1:4200`.

Если требуется запуск на конкретном адресе и порте, используется команда:

`npm start -- --host 127.0.0.1 --port 4200`

Назначение этой команды заключается в явном указании сетевого адреса и порта локального сервера. Результатом выполнения является запуск приложения по адресу `http://127.0.0.1:4200`.

Для проверки корректности сборки используется команда:

`npm run build`

Назначение команды состоит в создании production-сборки приложения без запуска локального сервера. В результате должна завершиться успешная компиляция проекта без ошибок.

Возможные ошибки при запуске:

- отсутствие установленного Node.js;
- отсутствие зависимостей проекта;
- занятый порт 4200;
- ошибки компиляции в исходных файлах.

Способы устранения ошибок:

- установить Node.js и `npm`;
- выполнить установку зависимостей командой `npm install`;
- освободить занятый порт или изменить номер порта;
- исправить ошибки в исходном коде и повторить сборку.

## 5 Порядок проверки работоспособности

## 6 Описание структуры пользовательского интерфейса

Пользовательский интерфейс приложения организован как последовательный маршрут. Это необходимо для того, чтобы пользователь не терялся в структуре экранов и мог проходить модули по порядку. Результатом является понятная логика взаимодействия, подходящая для ребенка младшего школьного возраста.

Основные экраны интерфейса следующие:

- загрузочный экран;
- главное меню;
- карта модулей;
- экран модуля;
- экран наград;
- финальный экран.

### 6.1 Загрузочный экран

На загрузочном экране пользователь видит стартовую иллюстрацию, персонажа, приветственный текст и шкалу загрузки. Назначение этого экрана состоит во введении в атмосферу приложения и подготовке к переходу в главное меню. Результатом является возможность начать путешествие после завершения анимации загрузки.

### 6.2 Главное меню

Главное меню предназначено для входа в основной маршрут приложения. Здесь пользователь видит название проекта, центральную иллюстрацию и кнопку начала путешествия. Результатом работы на данном экране является переход на карту модулей.

### 6.3 Карта модулей

Карта модулей показывает весь пользовательский маршрут. На ней размещены точки, соответствующие отдельным модулям. Назначение карты состоит в визуальном отображении последовательности прохождения. Пользователь может понять, какой модуль уже завершен, какой открыт в данный момент и какой станет доступен далее.

### 6.4 Экран модуля

Экран модуля используется для прохождения содержательной части приложения. Здесь последовательно отображаются сюжетные сцены, вопросы, видео, интерактивные задания и творческие действия. Результатом работы на этом экране является завершение модуля и переход к следующему этапу.

### 6.5 Экран наград

Экран наград отображает общее продвижение пользователя. На нем показываются искры, коллекция бейджей и сохраненные семейные результаты. Назначение этого экрана заключается в фиксации достижений и отображении итогов пройденного пути.

### 6.6 Финальный экран

Финальный экран открывается после завершения всех модулей. Он содержит итоговую информацию о прохождении и семейный сертификат. Назначение экрана состоит в завершении маршрута и закреплении общего результата.

## 7 Описание модулей приложения

Приложение включает четыре тематических модуля. Каждый модуль выполняет собственную образовательную и игровую задачу. Последовательное прохождение модулей необходимо для того, чтобы пользователь постепенно переходил от знакомства с историей к совместной деятельности, интеллектуальным заданиям и итоговому семейному результату.

### 7.1 Литературный модуль

Литературный модуль открывает путешествие. В нем пользователь знакомится с Пампалче, читает сюжетный материал, смотрит вводное видео и отвечает на вопросы по содержанию. Дополнительно в модуле предусмотрено творческое задание, связанное с семейными ценностями.

Назначение модуля состоит в формировании общего контекста путешествия и введении пользователя в тему семейного взаимодействия. Результатом прохождения становится понимание образа героини, включение в сюжет и получение первой награды.

### 7.2 Модуль «Сделаем вместе»

Данный модуль посвящен совместной практической деятельности. Пользователь проходит мастер-класс, выполняет действия по шагам, использует подсказки и при необходимости просматривает тематическое видео.

Назначение модуля заключается в переносе взаимодействия из цифровой среды в совместное семейное действие. Результатом становится выполненная работа и сохранение ее визуального результата через фотографию.

### 7.3 Модуль «Подумаем вместе»

Третий модуль ориентирован на словесные и логические задания. Пользователь отвечает на вопросы, выбирает варианты ответа и выполняет интерактивный кроссворд.

Назначение модуля состоит в закреплении понятий и смыслов через игровую интеллектуальную активность. Результатом прохождения является решение словесных задач и получение очередной награды.

### 7.4 Модуль «Приготовим вместе»

Четвертый модуль завершает маршрут практическим семейным действием. Пользователь смотрит тематическое видео, знакомится с последовательностью кулинарного задания и проходит завершающие шаги модуля.

Назначение этого этапа заключается в создании общего семейного результата, который воспринимается как итог всего путешествия. После завершения пользователь получает финальную награду и открывает итоговый экран.

## 8 Описание системы искр и наград

Система искр используется для отображения прогресса пользователя. Искры начисляются после завершения модулей и формируют общий счет. Это необходимо для того, чтобы пользователь видел накопительный результат прохождения и воспринимал каждый этап как значимое достижение.

Помимо искр, в приложении используются тематические бейджи. Каждый бейдж соответствует отдельному модулю. Такая схема позволяет не только показать общий прогресс, но и связать награду с конкретным типом деятельности.

## 9 Описание данных и логики работы приложения

Основная логика приложения строится на разделении кода и контента. Программный код отвечает за отображение экранов, переходы между ними, сохранение прогресса и обработку действий пользователя. Контентный файл содержит тексты, названия модулей, шаги, награды и ссылки на изображения и видео.

Такое разделение необходимо для удобства сопровождения. Если требуется изменить текст модуля, подпись к награде или маршрут шагов, это можно сделать в контентном файле без переработки всей программы.

Внутри модулей используются следующие типы шагов:

- диалог;
- выбор ответа;
- вопрос;
- рефлексия;
- видео;
- кроссворд;
- загрузка фотографии.

Переход между модулями выполняется только после завершения текущего модуля. Это правило необходимо для сохранения логики маршрута. Результатом является последовательное прохождение всех этапов без нарушения общей структуры путешествия.

## 10 Проверка пользовательских результатов

Проверка пользовательских результатов выполняется по нескольким признакам. Во-первых, пользователь должен иметь возможность пройти доступный модуль без ошибки перехода. Во-вторых, ответы, награды и фото-результаты должны сохраняться в локальном хранилище браузера. В-третьих, после завершения всех модулей должен открываться итоговый экран.

Для проверки можно использовать следующий порядок действий:

1. Запустить приложение локально.
2. Пройти загрузочный экран и главное меню.
3. Открыть первый модуль и завершить его.
4. Проверить появление искр и открытие следующего модуля.
5. Повторить действия для всех модулей.
6. Открыть экран наград и проверить отображение прогресса.
7. Убедиться, что после завершения всех модулей доступен финальный экран.

Если результат проверки соответствует указанной последовательности, приложение можно считать работоспособным с точки зрения пользовательского сценария.

## 11 Возможные ошибки и способы их устранения

В процессе работы могут возникнуть ошибки как на этапе запуска, так и при пользовательской проверке приложения.

К типовым ошибкам относятся:

- приложение не открывается в браузере;
- локальный сервер не запускается;
- не отображаются изображения или видео;
- не открывается следующий модуль;
- не сохраняются результаты пользователя.

Причины и способы устранения:

1. Если приложение не открывается в браузере, необходимо проверить, что локальный сервер действительно запущен и используется правильный адрес.
2. Если сервер не запускается, необходимо проверить наличие зависимостей и корректность команды запуска.
3. Если не отображаются медиафайлы, необходимо убедиться, что пути к изображениям и видео указаны правильно.
4. Если следующий модуль не открывается, необходимо проверить, завершен ли предыдущий этап и сохранился ли прогресс.
5. Если результаты не сохраняются, необходимо проверить доступность `localStorage` в браузере и отсутствие ограничений на локальное хранение данных.
